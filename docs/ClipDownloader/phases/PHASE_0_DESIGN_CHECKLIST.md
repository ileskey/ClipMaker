# ClipDownloader Phase 0 설계 작업 목록

상태: 설계 검토 완료 및 사용자 설계 확정 (2026-10-06). [Phase 0 상세 설계](PHASE_0_DESIGN.md)에 결정·근거·변경 계획·검증 절차와 전체 확정 기록을 남겼다. 체크 표시는 설계 검토 완료이며 구현·검증 완료를 의미하지 않는다.

## 1. 목적과 작업 범위

새 context에서 Phase 0 — Solution Bootstrap의 상세 설계를 확정하기 위해 확인하고 결정할 항목을 정리한다. 이번 산출물은 체크리스트이며, 구현 계획을 확정하거나 코드를 작성한 결과가 아니다.

Phase 0의 목표는 실행 가능한 WPF 앱, 기본 MVVM, 계층 경계, DI 방침, logging, 외부 도구 경로 관리 및 테스트 기반을 준비하는 것이다. 기존 솔루션과 앱을 활용하며, 처음부터 다시 생성한다고 가정하지 않는다.

다음 context에서는 설계 작업만 수행한다. 구현은 별도 요청 이후 진행한다.

- 단일 저장소에서 앱별 문서를 `docs/ClipDownloader`와 `docs/ClipEditor`로 분리한다.
- 다운로드 앱과 편집기는 서로의 전용 계층을 직접 참조하지 않는다.
- 공유 미디어 기능은 UI와 사이트별 다운로드 로직에 종속되지 않는다.
- Phase 0은 선행 구현 단계 없이 설계를 시작할 수 있다. Phase 1 상세 설계는 Phase 0 구현·검증 완료 후 시작한다.

## 3. 현재 상태와 다시 확인할 사항

이 체크리스트 작성 시 확인한 상태:

- `ClipMaker.slnx`는 `ClipDownloader/ClipDownloader.csproj`를 참조한다.
- 현재 WPF 프로젝트는 `net10.0-windows`, Nullable 및 ImplicitUsings 활성화 상태다.
- 프로젝트 파일에는 패키지 및 다른 프로젝트 참조가 선언되어 있지 않다.
- 앱별 문서와 요구사항은 `docs/ClipDownloader` 아래로 이동했다.
- 확인한 HEAD는 `fc96883b18c1d6856c92ad6b029d45e095e41e69`이며, `git status --short`에는 `docs/`가 미추적 상태로 표시되었다.
- 이번 작업에서는 빌드·테스트·앱 실행을 수행하지 않았다. SDK 설치·외부 도구 설치 상태도 확인하지 않았다.

새 context에서는 Git 상태와 관련 파일을 다시 확인한다. 위 정보는 현재 상태를 대신하는 영구적인 사실이 아니다.

문서 이동 이후 남아 있는 경로 불일치도 확인했다. PHASE_DESIGN의 요구사항 링크와 Phase 문서 경로, PROJECT_STRUCTURE_DESIGN의 요구사항 위치와 문서 트리, 아키텍처 명세의 상세 설계 링크 등이 이전 위치를 가리킨다. 새 설계의 기준 정리 작업에서 실제 경로에 맞춰 수정한다. 원본 문서는 이번 체크리스트 작성에서 수정하지 않았다. 이후 Phase 0 설계 검토에서 상대 링크·문서 경로와 트리를 실제 위치로 수정했다.

- [x] 설정 전달만 준비할지, 저장·로드까지 할지 현재 필요에 따라 최소 범위를 정한다. 설정 UI는 요구 없이 추가하지 않는다.

- [x] 자동 다운로드·업데이트·도구 동봉은 현재 범위에서 제외한다.

산출물: 계약·설정 모델 후보, 탐색 규칙, 누락·오류 정책과 Phase 1 인계 사항.

산출물: 의존성 표, 테스트 구성, 요구사항별 검증 계획.

## 5. 이번 상세 설계에서 제외할 항목

- Timecode·FPS 변환 알고리즘 상세 설계와 구현
- ProcessRunner, yt-dlp JSON 파싱, 다운로드·FFmpeg 클립 처리 구현
- CLI 호스트, 실제 사이트 테스트와 영상 다운로드
- 다운로드 UI, 여러 구간 큐, Preview, 브라우저 확장, 로컬 영상 기능
- ClipEditor 프로젝트·기능, 미래 사용만을 위한 공유 라이브러리 추가
- 배포·설치 프로그램·외부 도구 자동 업데이트

후속 기능의 연결 지점과 제약만 사전 검토할 수 있으며, Phase 1 상세 설계는 Phase 0 구현·검증 완료 후 진행한다.

## 6. 새 context의 최종 산출물

상세 설계는 이 체크리스트와 구별하여 같은 폴더의 `PHASE_0_DESIGN.md`에 작성한다. 기본 항목은 다음과 같다.

1. 상태, 목표, 범위와 제외 범위
2. 기준 문서·소스 상태와 현재 구조
3. 목표 구조·파일 변경 계획·참조 관계
4. MVVM·DI·앱 수명·logging·도구 경로 관리의 확정 설계
5. 의존성 선택과 설계 결정의 근거
6. 구현 순서와 완료 조건별 검증 계획
7. 미해결 사항과 Phase 1 인계 사항

설계 확정 전에는 “설계 중”으로 표시한다. 확정 시 필수 결정 사항과 차단 사항을 정리한다. 설계 확정만으로 Phase 0 구현 완료나 Phase 1 시작 조건 충족을 선언하지 않는다.
